# Local Testing

Use this workflow to run the Gleip CLI from the repository without publishing it to npm.

```sh
pnpm install
pnpm gleip --help
```

Create a temporary target repository:

```sh
mkdir -p /tmp/gleip-test
cd /tmp/gleip-test
git init
```

Run agent setup from this repository against the temporary target:

```sh
cd /path/to/Gleip
pnpm gleip --cwd /tmp/gleip-test init
pnpm gleip --cwd /tmp/gleip-test init claude
pnpm gleip --cwd /tmp/gleip-test init gemini
pnpm gleip --cwd /tmp/gleip-test doctor --agents
```

Inspect the generated files:

```sh
ls -la /tmp/gleip-test
cat /tmp/gleip-test/AGENTS.md
cat /tmp/gleip-test/CLAUDE.md
cat /tmp/gleip-test/GEMINI.md
```

Expected results:

- `.gleip.yml` exists.
- `GLEIP.md` exists.
- `.gleip/` exists.
- `AGENTS.md` contains exactly one Gleip-managed section.
- `CLAUDE.md` contains exactly one Gleip-managed section.
- `GEMINI.md` contains exactly one Gleip-managed section.
- Generated workflow commands use `npx --no-install gleip`.
- Re-running init does not duplicate managed sections.

## Testing the workflow manually

The normal product flow is for agents to run these steps. To test them directly from the source repository:

```sh
pnpm gleip --cwd /tmp/gleip-test preflight "Fix the checkout discount calculation bug without changing payment provider integration or checkout routing."
pnpm gleip --cwd /tmp/gleip-test brief
pnpm gleip --cwd /tmp/gleip-test validate-plan "Update the discount calculation and its focused checkout tests."
pnpm gleip --cwd /tmp/gleip-test status
pnpm gleip --cwd /tmp/gleip-test stop
```

## Testing context compression locally

Create a large local output file, compress it, retrieve the exact original, and
inspect stats:

```sh
node -e "for (let i=0;i<200;i++) console.log('PASS repeated.test.ts'); console.log('FAIL focused.test.ts')" > /tmp/gleip-output.txt
pnpm gleip --cwd /tmp/gleip-test compress --audit --json < /tmp/gleip-output.txt
pnpm gleip --cwd /tmp/gleip-test compress --type test_output < /tmp/gleip-output.txt
pnpm gleip --cwd /tmp/gleip-test retrieve <sha256-reference> > /tmp/gleip-output.retrieved.txt
pnpm gleip --cwd /tmp/gleip-test run -- node -e "for (let i=0;i<200;i++) console.log('PASS repeated.test.ts')"
pnpm gleip --cwd /tmp/gleip-test stats --json
```

Expected results: only execution evidence is compressed, `.gleip/context/` is
ignored, retrieval reproduces the original output, and active task artifacts under
`.gleip/` remain separate from compression state.

## Dogfooding This Repository

Gleip is used in this repository during local development. Commit the repo-level Gleip policy and documentation files:

- `.gleip.yml`
- `GLEIP.md`
- `AGENTS.md`

Do not commit local session state from `.gleip/`. These files are generated by local commands and are ignored:

- `.gleip/session.json`
- `.gleip/brief.md`
- `.gleip/scope-budget.json`
- `.gleip/status.md`
- `.gleip/baseline.json`
- `.gleip/state.json`
- `.gleip/context/index.json`
- `.gleip/context/objects/<sha256>`

Use `npx gleip stop` to reset an active session. Remove `.gleip/` only when intentionally clearing all local Gleip state.

## Testing Repository Cleanup

Preview and run cleanup against the temporary target:

```sh
pnpm gleip --cwd /tmp/gleip-test uninstall --dry-run
pnpm gleip --cwd /tmp/gleip-test uninstall
```

Verify `.gleip/`, `.gleip.yml`, `GLEIP.md`, and empty generated agent instruction files are removed. Gleip-managed sections should be removed from `AGENTS.md`, `CLAUDE.md`, and `GEMINI.md` without deleting unrelated instructions. Package removal remains a separate `npm uninstall gleip` step.
